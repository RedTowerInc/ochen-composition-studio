## Найденные дефекты

### RA01 · P2 — неизвестное слово ошибочно превращается в поддержанную тему

Вход: режим «По смыслу», текст **«Президент»**. Также воспроизводится на **«Эпидемия»**.

Ожидание по M04/M05 и согласованному ограниченному словарю: запрос уточнения, если тема отсутствует. Фактически возвращаются `lamp`, `puzzle`, `pen` и уверенное пояснение «Подбор по теме “идеи и поиск решений”». При пустом холсте результат сразу применяется; при существующей сцене предлагаются неверные варианты.

Причина: `src/core/semantics.ts:152`, поиск `text.includes(word)` для фрагмента `иде` без границы слова. Исправление границ имён объектов в прежнем аудите не закрыло поиск тематических фрагментов.

Доказательства: два новых красных unit-теста; сценарий «Президент» воспроизведён в production в Chrome и Firefox. Снимки `chromium-unsupported.png`, `firefox-unsupported.png`, фактический текст рядом. Контроль «Квантовая запутанность» штатно отклоняется — тест не требует универсального понимания любой метафоры.

Исправлять общую нормализацию/сопоставление тематических слов, сохраняя корректные словоформы. Не добавлять исключения только для двух проверочных слов.

### RA02 · P2 — явно исключённая тема выбирается как основная

Вход: **«Не учиться, а отдыхать»**.

Допустимые результаты: подбор по отдыху либо честный запрос уточнения. Фактически выбираются `book`, `pen`, `lamp`, пояснение — «обучение и знания». Причина: положительные и отрицательные упоминания считаются одинаково; пересекающиеся фрагменты `учит`/`учить`/`учиться` дополнительно увеличивают вес одной темы.

Источник: `src/core/semantics.ts:149`–`158`. Доказательства: новый unit-тест, production Chrome и Firefox, `*-negation.png` и `*-negation.txt`. Это нарушение M04, а не требование встроить полноценную NLP-модель. Достаточна консервативная обработка явного отрицания/неоднозначности с уточнением.

### RA03 · P2 — положительные, но несогласованные габариты каталога принимаются

В manifest изменён только `book.variants.L.main.viewBox[0]` на исходное значение +10000; сам оригинальный SVG оставлен без изменений. Все размеры остаются конечными и положительными.

Ожидание S10: отклонение несогласованного ресурса до запуска редактора. Фактически каталог объявляется готовым, генерация и экспорт работают без предупреждения, а книга перемещается далеко за холст: её экранный bounding box в Chrome начинается примерно в `x=-987`, ширина около 249 px. На композиции книга отсутствует, хотя модель считает её присутствующей.

Причина: `src/core/catalog.ts:53`–`63` проверяет форму и знак чисел; `sanitizeSvg` не сравнивает реальный viewBox корня с metadata. `instanceTransform`, `src/core/svg.ts:250`, доверяет metadata.

Доказательства: unit с исходными 40 SVG, production Chrome и Firefox, `*-manifest.json` и `*-manifest.png`. Контроль с неизменённым manifest успешно загрузил все 40 вариантов.

**Граница воздействия:** в фактически поставляемом каталоге повреждения нет, его SHA проверены. Пользователь не загружает произвольные SVG/manifest. Это дефект проверки отказного сценария и возможной несогласованной поставки, не доказательство исчезновения объектов при штатной работе. Нужно сравнивать metadata с самим SVG до готовности каталога.

### RA04 · P3 — у загрузки каталога нет собственной границы ожидания

При намеренно незавершённом HTTP-запросе одного SVG приложение продолжает показывать загрузку без Retry. В Chrome и Firefox после перевода часов приложения вперёд на 120000 мс это состояние сохранилось; после освобождения запроса редактор штатно загрузился.

Это **контролируемое наблюдение**, а не два красных теста и не две реальные минуты ожидания сети. Таймеры браузерной сети не ускорялись. Подтверждено отсутствие таймаута приложения в `loadCatalog`, а не бесконечное зависание при любом сетевом сбое.

Источник: `src/core/catalog.ts:20`, `84`, `App.tsx:89` и далее. Разумное улучшение устойчивости — конечное ожидание с отменой запроса и тем же Retry. Отдельного численного deadline для этой загрузки в исходном ТЗ нет; этот пункт не приравнен к обязательным красным M04/S10.

## Интерфейс и итоговые изображения

Заново проверены семь размеров окна. Ширина горизонтального рисунка: 1440×900 — 643,55 px; 1366×768 — 588,44; 1280×720 — 503,11; телефон 390×844 — 312; 320×740 — 242. Для квадратной/вертикальной сцены на 1024×768 и 768×1024 занято практически 100% доступного вписывания. Горизонтального переполнения нет.

Настоящий Chrome zoom через Settings в отдельных профилях: 125% дал CSS viewport 1152×720, 200% — 720×450; drag, Undo и экспорт прошли. CSS zoom или подмена DPR вместо zoom не применялись. Физические сенсорные устройства не проверялись.

Путь «ввести → собрать → довести → скачать SVG» понятен. Файловые операции отделены меню «Проект», точные объекты доступны через библиотеку/слои. Убраны ложные resize-маркеры. Статус записи, размер и число объектов полезны; технических revision/hash, отладочных панелей, сообщений о внутренней архитектуре в штатном интерфейсе нет. На узком экране Undo/Redo доступны в меню проекта. Ошибки записи не перекрывают способы сохранить проект.

Небольшой реальный пробел: подпись «Подбор по смысловым темам» слабо объясняет границу режима. При исправлении RA01/RA02 уместна одна короткая подсказка с поддерживаемыми темами/предложением уточнить смысл. Отдельная панель помощи, новые режимы или расширение функций не нужны. У вспомогательных подписей мелкий шрифт; это скорее запас для аккуратной доводки, чем обнаруженная блокировка действий.

Повторно просмотрены исходные примеры Figma, оба сохранённых контактных листа 56 сцен и новый лист 18 SVG из экспортной матрицы. **Кадрирование разрешено оригинальными примерами.** Обрезанный край фонового предмета или узнаваемой лампы не нарушает ТЗ сам по себе. Нарушением было бы изменение геометрии/относительных размеров либо утрата узнаваемого главного объекта. На проверенном исправленном корпусе прежние гигантские фрагменты не воспроизводятся. Компоновка достаточно осторожная, иногда разреженная; эстетика уступает ручным примерам Figma, но оснований запрещать любое кадрирование нет. Ручной выход за край также разрешён и точно экспортируется.

## Пробелы строгой приёмки и границы доказательств

Эти пункты нельзя записывать как ошибки программы без воспроизведения, но нельзя и объявлять полностью пройденными:

| Пункт общей матрицы | Подтверждено | Что не подтверждено полностью |
| --- | --- | --- |
| D02/D07/D08/D11/D12 и протокол повторов | Контракты очереди, CAS, копия, double New и поздний ACK проходят; в предыдущем цикле RG10/RG15/D12 дали 60/60 повторов | Предписанные 10 повторов всех порядков для всех перечисленных сценариев. 60 — это 3 сценария ×10 ×2, не вся матрица гонок. Отдельный timeout медленной копии D08 не подтверждён |
| C09 | Ограниченный поиск и fallback есть в коде; обычный и случайный корпуса завершаются | Принудительное попадание в запасную ветку. В новом random-корпусе fallback=0; это нельзя считать её успешным исполнением |
| G03–G08 | 100 обратных завершений LatestJob в unit, A/B импорты и поздние файлы в браузере | Полная требуемая серия повторений всех управляемых порядков каждого пользовательского потока |

Старый сеанс не включал периодические переходы New/open/copy; отдельные тесты переходов не равны смешанному длительному сеансу из плана |

Исторические результаты независимого редактора в этом аудите повторены заново. Чистая переустановка npm ci/build из source ZIP в этом прогоне не повторялась: использован прежний успешный результат для неизменённых source/lock-файлов, дополненный новой сборкой и проверкой SHA. Гарантия отсутствия любых утечек/всех ошибок не выводится ни из 30 минут, ни из числа зелёных тестов.

WebKit, другие ОС, физический touch и нативный файловый диалог SVG-edit не проверялись. SVG-edit импортировал через публичный API, после чего узел менялся через UI и сохранённая копия открывалась повторно. Не заявляется, что вся браузерная матрица выполнялась в Firefox: восемь экстремальных legacy-сценариев настроены только для Chrome.

## Минимум перед окончательным допуском

1. Исправить RA01/RA02 общей логикой сопоставления слов/неоднозначности. Новые отрицательные тесты сделать зелёными без специальных ответов под контрольные строки; проверить прежние темы и словоформы.
2. Исправить RA03: проверка согласованности metadata и фактического SVG, атомарный отказ и восстановление. Проверить все 40 оригиналов положительным контролем.
3. Закрыть либо явно пересогласовать перечисленные пробелы обязательной матрицы: повторения, медленная копия, принудительный fallback, смешанный длительный сеанс. Не подменять это общим количеством тестов.
4. Повторить затронутые проверки и полную регрессию исправленного продукта; пересобрать поставку и проверить именно её. Отдельно решить способ передачи работодателю с учётом текущего закрытого доступа.

RA04 разумно устранить в том же небольшом проходе, но не расширять ради него архитектуру. Новые функции, серверный AI и редизайн не требуются.

## Воспроизведение и артефакты

Из папки app, с установленными зависимостями и браузерами:

```powershell
npm run build
npx vitest run
$env:OCHEN_AUDIT_RUN = 'new-distinct-audit-id'
npx vitest run --config vitest.regression.config.ts
npx playwright test --config playwright.regression.config.ts
npx vitest run --config verification/re-audit-0.1.1-2026-11-11/probes.config.ts
npx playwright test --config verification/re-audit-0.1.1-2026-11-11/browser-probes.config.ts
```

Последние две команды на 0.1.1 возвращают ненулевой код — это реальные красные проверки, не разрешённые исключения. При новом прогоне сохранять результаты в другом каталоге, а не затирать доказательства аудита.

Основные файлы доказательств: `core-unit.json`, `probes.json`, `browser-probes.json`, `legacy-browser.json`, `stress-layouts.json`, `source-fingerprint.json`, `package-check.json`, `benchmark.json`, `ui/report.json`, `exports/report.json`, `svg-editor/report.json`, `ready-zip/report.json`, `published/report.json`. Браузерные traces и снимки падений сохранены локально в `probe-traces/`.

Сбой первого запуска отдельной legacy-конфигурации был ошибкой обвязки: относительный cwd сервера указывал на папку отчёта. Исправлен только cwd теста; полноценный прогон дал 38/38. JSON Playwright первоначально записались во вложенную папку из-за относительности outputFile к конфигурации; исходные файлы сохранены и скопированы в корень аудита, пути следующих запусков исправлены. Первичный unit-отчёт `probes-initial.json` содержит те же четыре отрицательных результата до добавления двух положительных контролей и сокращения дампа DOM. Эти изменения обвязки не являются дефектами продукта и не меняли критерии проверок.
