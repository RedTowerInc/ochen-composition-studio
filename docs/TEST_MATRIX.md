# План проверки приложения

Матрица приёмки согласованного решения. Фактические результаты и неприменимые сценарии записаны в [TEST_REPORT.md](../TEST_REPORT.md). Таблица ниже сохраняет исходные ожидаемые результаты.

P0 — потеря данных, нарушение исходных ограничений, сломанный основной экспорт или зависание. P1 — обязательный сценарий, корректность и восстановление. P2 — дополнительная нагрузка и совместимость за пределами основного сценария.

## Гонки и изоляция

Тесты используют управляемые promise, barriers и подменённые задержки. Требуется воспроизвести нужный порядок завершения операций, а не надеяться на случайное совпадение.

| ID | Приоритет | Сценарий | Ожидаемый результат |
|---|---|---|---|
| C01 | P0 | Сборка A медленная, B быстрая; A завершается последней | Применим только актуальный результат B |
| C02 | P0 | Во время сборки поменять палитру, формат, проект или выполнить Undo | Несовместимый ответ не переписывает новое состояние |
| C03 | P0 | Экспорт запущен, затем перемещён объект и заменена палитра | В файле одна целостная версия; прежнее/новое не смешаны |
| C04 | P0 | Две вкладки одного контекста читают revision=7 и одновременно сохраняют | Только одна пишет revision=8; вторая получает конфликт без потери своей копии |
| C05 | P0 | Поздно завершить сохранение старой сцены после новой правки | Новая сцена не отмечается сохранённой до собственного commit |
| C06 | P0 | 10 независимых BrowserContext строят разные сцены одновременно | У каждого свой документ, результат, палитра и история |
| C07 | P1 | Удалить выбранный объект при завершении async-предпросмотра | Объект не появляется снова; выделение согласованное |
| C08 | P1 | Два импорта палитры с обратным порядком завершения чтения | Побеждает актуальный запрос, а не последний случайный ответ |
| C09 | P1 | Клонировать объект много раз, затем экспортировать | Нет совпадений instanceId и SVG-id |
| C10 | P1 | Worker отвечает после отмены/смены документа, если Worker есть | Ответ отброшен; каталог и другая сцена не изменены |
| C11 | P1 | Быстрые повторные команды сборки и экспорта | Ограниченное число задач; нет утечки обработчиков и URL |
| C12 | P1 | Потеря фокуса, pointercancel/lostpointercapture во время drag | Нет зависшего жеста; Undo остаётся согласованным |

## Стресс и длительная работа

| ID | Приоритет | Сценарий | Критерий |
|---|---|---|---|
| S01 | P1 | 1, 10, 25, 50 экземпляров реальных сложных SVG | Измерены время сборки, экспорта и отзывчивость; лимиты обоснованы |
| S02 | P1 | 500–1000 команд добавления/поворота/удаления/Undo/Redo | Инварианты соблюдены; история ограничена; нет необработанной ошибки |
| S03 | P1 | Предел и превышение числа объектов, размера файла, холста и длины ввода | Пределы валидируются; отказ безопасный и предсказуемый |
| S04 | P1 | 100 повторных экспортов и отменённых сборок | Blob URL/задачи освобождаются; отсутствует очевидный рост удерживаемых ресурсов |
| S05 | P2 | 30 минут редактирования с повторениями | Сцена сохраняется; оценён тренд памяти после стабилизации, без требования идеальной линии GC |
| S06 | P2 | CPU throttling, узкое окно, быстрые последовательные переключения | Интерфейс сообщает о работе, отмена доступна; нет повреждения документа |

Для fast-check: минимум 1000 воспроизводимых сценариев ядра с последовательностями до 100 команд, если это укладывается в бюджет CI. Проверяем уникальность id, конечность чисел, допустимые ссылки, пределы, эквивалентность сериализации и корректность Undo. При ошибке сохраняем seed/path и минимальную последовательность.

Рабочие целевые значения для эталонного локального стенда: сборка без внешнего AI при 20 экземплярах p95 < 500 мс, экспорт p95 < 1000 мс, обычное редактирование без заметной блокировки главного потока. Это цели измерений, а не уже подтверждённые характеристики. После аудита сложных SVG фиксируем стенд, размеры данных и честные результаты.

## Если включён AI-адаптер

Отдельно проверяем на собственном стенде со stub-провайдером: 1 → 10 → 25 → 50 параллельных запросов, ограниченную очередь, переполнение и восстановление. Не отправляем нагрузку платному/чужому API.

Проход: нет смешивания requestId/ответов пользователей; размер очереди ограничен; перегрузка возвращает предсказуемый 429/503; таймауты завершают задачи; после снятия нагрузки сервис восстанавливается. Латентность, число активных запросов и величина памяти записаны. Если адаптер не реализован, эти проверки помечаются «не применимо», а не «пройдено».

## Интерфейс, доступность и визуальная приёмка

- Основной сценарий мышью и клавиатурой; Delete/Undo не вмешиваются в редактирование текста.
- Видимые фокусы, подписи кнопок, состояния disabled/busy/error и сообщение о сохранении соответствуют реальности.
- Размеры окна 1440, 1280, 1024, 768 и 390 px; масштаб браузера 125% и 200%; нет перекрытия обязательных действий.
- Chromium — полная обязательная матрица, Firefox — основной сквозной сценарий. WebKit — по оставшемуся времени; отсутствие проверки указывается.
- Визуальные эталоны: три палитры × S/L × три формата на выбранных контрольных сценах. Скриншоты снимаются в закреплённых браузере/ОС/шрифте.
- Эстетику оцениваем вручную по референсам Figma: фокус, свободное место, кадрирование, перекрытия. Автотест не доказывает, что композиция красива.

## Как оформляем результат

В `TEST_REPORT.md` после реализации: commit, окружение, команды, продолжительность, пройденные/непройденные/непроверенные ID, seed ошибок, trace/скриншоты и экспортированные SVG. Первым абзацем — блокирующие проблемы и практические ограничения. Наличие теста без успешного запуска не считается прохождением.
