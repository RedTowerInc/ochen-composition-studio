## 2. Правила достоверности

- У каждой проверки — наблюдаемый результат, а не только отсутствие исключения или наличие кнопки.
- Поток сохранения проверяется чтением фактической записи и повторным открытием. Надпись «Сохранено» не является единственным доказательством.
- При гонке задаём порядок через управляемые Promise/барьеры/остановленные часы. `clock.install()` без остановки часов не фиксирует границу времени. Используем заранее установленное время и заведомо будущую точку остановки, не `Date.now()+1` через несколько удалённых вызовов.
- Ожидание условия через `expect.poll` допустимо; случайный `sleep` вместо барьера не подтверждает нужный порядок.
- Нет ослабления критериев после неудачного результата, автоматических retry и выборки только удачных сцен.
- Нормальный ввод проверяется наряду с повреждённым: защита не должна отвергать исправный SVG/JSON.
- Проверки по модели, браузерному рендеру, XML и независимому редактору дополняют друг друга. Нельзя заменить все уровни одним и тем же helper из реализации.
- Дефект тестового стенда исправляется и отмечается отдельно; его падение не увеличивает число ошибок продукта. Baseline принимается только после проверки причин падений.

Обязательные уровни: U — unit/property, I — интеграция хранилища/ресурсов, B — реальный браузер, V — визуальная приёмка, E — независимый редактор. Обязательные неисполненные строки остаются «не проверено» и блокируют итоговое утверждение о готовности.

### Независимый расчёт видимости

Из оригинального SVG каждого экземпляра строится маска alpha на прозрачном фоне. Полная площадь измеряется в его полной области габаритов при той же плотности выборки. Вторая маска ограничивается холстом; третья учитывает alpha вышележащих экземпляров. Сравниваются суммы alpha, а не цвет фона и не число пикселей bounding box.

Фиксировать разрешение рендера и допуск пограничного antialiasing. Проверку выполнять на достаточно большом масштабе, например длинная сторона холста 1024 px; пограничные случаи перепроверять на 2048 px. Не снижать нормативную долю из-за округления. Маски и слой за слоем сохранять для неудачных случаев.

Пиксельные измерения используются только в QA. Продукт может использовать более дешёвую консервативную геометрическую проверку. Итоговая узнаваемость дополнительно проверяется вручную.

## 12. Артефакты и заключение

Для каждого именованного прогона: commit и fingerprint, окружение/версии, команды, число случаев, ожидаемые/фактические результаты, seed, JSON и HTML отчёт. При падении: trace, снимок, минимальный вход, исходный/экспортированный SVG или запись хранилища по типу дефекта.

Отдельно сохраняются:

- исходный аудит и проверенный baseline с красными регрессиями;
- результаты после каждого исправленного блока;
- финальные визуальные листы и сравнительные изображения «до/после»;
- настоящий 30-минутный журнал, а не экстраполяция короткого теста;
- три SVG + JSON проекта + новая демонстрация из исправленной версии;
- независимая проверка SVG и проверка чистого ZIP/опубликованного сайта.

Итог по каждому A01–A06: **исправлено и подтверждено / исправлено, но не проверено / не исправлено**. Итог по каждой обязательной проверке: **пройдено / не пройдено / не проверено / неприменимо с причиной**. Красная обязательная проверка, нестабильный тест или неисполненный обязательный пункт сохраняют вердикт «к сдаче не готово».
