## Что изучено

Сравнение сделано по официальным страницам продуктов и их документации. Это исследование возможностей и подходов; платные тарифы не приобретались, нагрузочные измерения чужих сервисов не проводились. Под «лучшими» здесь понимаются наиболее подходящие референсы для конкретного задания, а не общий рейтинг рынка.

Вывод для проекта: отдельный компактный редактор под правила этой библиотеки. Универсальные редакторы добавляют инструменты изменения геометрии, которые здесь запрещены, и усложняют ограничение действий пользователя. Чужие иллюстрации в результат не включаем: используем только библиотеку работодателя.

## Выбранные технические подходы

1. **React + TypeScript + Vite, нативный SVG.** Состояние сцены отделено от DOM; команды редактирования проходят через чистый reducer. React требует чистоты reducer, что подходит для воспроизводимых команд и Undo/Redo: [React](https://react.dev/reference/react/useReducer). TypeScript проверяем отдельной командой `tsc --noEmit`: Vite сам выполняет транспиляцию, а не проверку типов: [Vite](https://vite.dev/guide/features).
2. **Встроенные группы в экспортируемом SVG.** У каждого экземпляра свои идентификаторы градиентов, масок и clipPath. Избегаем внешних ссылок и зависимости готового файла от сайта. Ограничения наследования CSS и внешних ссылок у `<use>` описаны в [MDN](https://developer.mozilla.org/en-US/docs/Web/SVG/Reference/Element/use); виды внутренних ссылок — в [SVG Linking](https://developer.mozilla.org/en-US/docs/Web/SVG/Guides/Linking).
3. **IndexedDB через Dexie, сохранение с проверкой версии.** Проверка текущей версии и запись следующей происходят в одной readwrite-транзакции. Сериализация транзакций сама по себе не заменяет проверку версии: [W3C IndexedDB](https://www.w3.org/TR/IndexedDB/), [Dexie.transaction](https://dexie.org/docs/Dexie/Dexie.transaction()).
4. **Отмена задачи и проверка актуальности результата.** AbortController помогает отменить поддерживаемые операции, но дополнительно проверяем идентификатор запроса и версию исходной сцены: [MDN AbortController](https://developer.mozilla.org/en-US/docs/Web/API/AbortController).
5. **Проверка SVG перед использованием.** Для разбора и очистки применим строгий список разрешённых элементов/атрибутов и DOMPurify с SVG-профилем. Одной очистки недостаточно для ограничения количества узлов, размера документа и внешних ссылок. Изменения после очистки тоже требуют контроля: [DOMPurify](https://github.com/cure53/DOMPurify).
6. **Поведенческие и визуальные проверки.** Playwright даёт отдельные BrowserContext для независимых посетителей. Для двух вкладок одного профиля, наоборот, используем две Page в одном контексте: [Isolation](https://playwright.dev/docs/browser-contexts), [Best practices](https://playwright.dev/docs/best-practices). Скриншотные эталоны сравниваем в закреплённом окружении: [Visual comparisons](https://playwright.dev/docs/test-snapshots).
7. **Случайные последовательности действий.** fast-check проверяет модель редактора и сохраняет seed для воспроизведения ошибки. Модель должна быть проще реализации: [Model based testing](https://fast-check.dev/docs/advanced/model-based-testing/).
8. **Если добавим серверный AI-адаптер — отдельная нагрузочная проверка.** k6 позволяет фиксировать численные критерии прохождения: [Thresholds](https://grafana.com/docs/k6/latest/using-k6/thresholds/). Тестирование выполняем на собственном локальном стенде с подменённым AI-провайдером.

## Что подтвердилось при реализации

- Исходники штатно экспортированы из Figma: два полных векторных листа, 40 групп для десяти семейств, 3026 внутренних узлов. Растровых вставок в каталог не включено. Каждый вариант связан с sourceNodeId и SHA-256.
- Подготовка сохраняет геометрию; очистка и три перекраски проверены для всех вариантов. Относительные размеры задаёт общий масштаб исходного набора L:1 / S:2.
- Формат палитры работодателем не задан. Реализован документированный JSON с восемью именованными ролями и скачиваемым образцом.
- Внешний AI-провайдер не подключён. Работает проверяемый словарь тем и тегов, неизвестные смыслы требуют уточнения.
- Выполнены 22 теста ядра, 38 браузерных сценариев, измерения, production-сравнение и проверка в независимом SVG-edit. Точные результаты и границы находятся в `../app/TEST_REPORT.md`.

Исследование возможностей аналогов не превращается в заявление, что проверены их платные функции или нагрузочная устойчивость.
